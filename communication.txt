TRACK 1: STORAGE AND SECURITY ENGINE
1. Move from a single encrypted JSON blob to a structured, encrypted, queryable store: SQLite (WASM + OPFS in browser, better-sqlite3 in desktop/server) with Drizzle ORM and field- or page-level encryption. Chats, messages, attachments, memories, prompts, agents, and documents become tables with indexes and full-text search (FTS5).
2. Key hierarchy: a random master data key wrapped by (a) password-derived KEK (use Argon2id via WASM instead of PBKDF2, with a migration from PBKDF2), (b) optional WebAuthn passkey (PRF extension) unlock, (c) a printable recovery key. Support password change without re-encrypting all data (rewrap the master key only).
3. In-app first-run setup (no hardcoded verifier or salts), auto-lock, memory zeroization where possible, secure clipboard clearing, and a panic "wipe now" action.
4. Encrypted, versioned backup/export/import (single file, streaming, integrity-checked), plus scheduled local backups on desktop.
5. Provider key storage: OS keychain on desktop (Keytar/Tauri keyring), AES-GCM file store as fallback; per-key usage limits and a spend cap per connection.
6. Security tests: tamper tests, KDF parameter tests, fuzzing of parsers (SSE, import files), CSP verification, and an automated scan that no secret patterns exist in the repo.
EXIT: 100k messages searchable under 100 ms; wrong-password, tamper, and migration tests pass.
